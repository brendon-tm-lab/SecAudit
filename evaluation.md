# Evaluation against commercial products

**Updated: 2026-10-29.** Scores one run of the current SecAudit build against the products in the supplied screenshots, using the files the build generated. This is an engineering assessment, not a benchmark or certification.


## Evidence used

- **Generated by SecAudit:** report.json (report e63a697a…, created 28 October 2026 23:20 UTC, profile insecure-file-uploads, 1 target), findings.sarif, ledger.json, manifest.json, signature.ed25519 and public_key.pem (the signed evidence pack).
- **Screenshots:** SecAudit Run Monitor beside Task Manager, McAfee Premium scan result, Windows Security scan options, Microsoft Defender command-line scans, and File Explorer showing the test folder.
- **Documentation:** application functions, architecture, installation, Strix integration and lab training references (Appendices A to E).
- **Test sample:** one folder of third-party Microsoft activation scripts plus an Office installer archive, a kind of content commercial antivirus products commonly flag. SecAudit reads it and does not execute it.

## Method and limits

- Ten criteria, each scored 0 to 5 and weighted to a total of 100 (weight × score ÷ 5). Scores are judgement from the evidence. The basis column marks each as **O** (observed in the supplied files or screenshots) or **G** (general public product knowledge, not tested here).
- One sample and one run per product. Scope was not identical: Defender scanned the folder by command line, McAfee scanned 18 items of unstated scope, and SecAudit considered 36 files in the folder.
- Defender's output does not list which files were detected, so file-level agreement between products cannot be scored.

## How to read the scores

- SecAudit is a review and evidence tool, not an antivirus or XDR. It scores low on protection criteria by design and should not replace Defender or McAfee.
- On the review and audit lens SecAudit scores 76%, ahead of Defender (47%) and McAfee (38%), because of scope control, honest coverage reporting and verifiable evidence.
- Scores marked G are indicative; check them against vendor documentation before using them outside the company.

## Conclusion

In this run SecAudit behaved honestly: stale signatures and the failed model call were shown as unavailable or incomplete, scope stayed explicit, and the evidence pack verifies. What holds it back is the content of its findings, which lack real evidence and do not yet match the clarity of a commercial detection. The best positioning is as a complement: use Defender or McAfee to detect and remove, and SecAudit to scope, explain and document the decision.
